# Groups & Google sign-in — implementation plan (2026-09-27)

Spec: `docs/superpowers/specs/2026-09-27-groups-design.md`. Branch: `feat/groups`.

Ground rules for every task:
- This is Next 16. Read the relevant guide in `node_modules/next/dist/docs/`
  before using any Next API you're unsure of (e.g. `middleware` is now `proxy`).
- Better Auth: use the v1.6.x docs (Context7 id `/better-auth/better-auth/v1.6.23`).
  Don't invent APIs.
- Prisma 7 with the `prisma-client` generator outputs to `src/generated/prisma`.
  The DB in `.env` is local Postgres, so `npx prisma migrate dev` is safe.
- Match the existing style: Tailwind dark neutral/emerald palette, `PageShell`,
  `PageHeader`, `Card`, mobile-first, `{ error?: string }` action results.
- `npm test`, `npx tsc --noEmit` and `npm run lint` must pass at the end of each
  task. Commit at the end of each task with a `feat:`/`fix:` message.

4. Generate a migration with `npx prisma migrate dev --create-only --name groups`,

   then add NOT NULL + FKs. Insert a `GroupInvite` for `logontokartik@gmail.com`.
   Swap the unique index on `Player.name` for `(groupId, name)`. Apply with
   `npx prisma migrate dev`.
5. `instrumentation.ts`: require `BETTER_AUTH_SECRET`, `GOOGLE_CLIENT_ID` and
   `GOOGLE_CLIENT_SECRET` instead of `POKER_EDIT_PASSWORD`. Update `.env.example`.
   Add placeholder values to local `.env` for the new vars (don't print `.env`).
6. Delete `src/lib/auth-core.ts` and its test. The app won't fully compile until

## Task 2 — Access helpers (`src/lib/access.ts`) + tests
- `getViewer()`: calls `auth.api.getSession({ headers: await headers() })` and
  returns the user or null.
- `claimInvites(user)`: only when `user.emailVerified`. In one transaction,
  upsert a GroupMember for every invite whose email equals the lowercased user
  email, then delete those invites.
- `isGroupAdmin(userId, groupId)`, `requireGroupAdmin(groupId)` (throws
  `Error('Unauthorized')` when there's no viewer or no membership, and returns
  the user otherwise), and `getGroupForViewer(slug)` returning `{ group,
  isAdmin, viewer }` or null.
- `slugify(name)` goes in pure `src/lib/slug.ts`: lowercase, non-alnum→`-`,
  collapse and trim dashes, cap at 40. If the result is shorter than 3 chars,
  use `'group'`.
- Vitest: unit tests for `slugify`. For `requireGroupAdmin`, mock `@/lib/auth`
  and `@/lib/db` to cover: no session, session without membership, and admin.

## Task 3 — Group-scoped server actions
- `src/app/actions/games.ts` and `players.ts`: replace `guard()` with per-record
  checks. Load the record (game / gamePlayer→game / player / buyIn chain) to get
  `groupId`, then `requireGroupAdmin(groupId)`, returning `{ error: 'Unauthorized' }`
  on throw.
- `createGame(groupId, prev, formData)`: bind `groupId` from the page. Admin check
  first. Player lookups and creation are scoped to the group. Redirect to
  `/g/<slug>/game/<id>`.
- `createPlayer(groupId, name)`. Name uniqueness is per group.
- Revalidate the new paths (`/g/<slug>`, `/g/<slug>/game/<id>`, `/v/<viewSlug>`,
  `/g/<slug>/players`). Add a small `revalidateGame(game, slug)` helper.
- Fold in the spec's three bug fixes (`addPlayerToGame`, `removePlayerFromGame`,
  `setMiscAdj`).
- New `src/app/actions/groups.ts`:
  - `createGroup(prev, formData)`: signed-in user required; unique slug with a
    random suffix on collision; the creator becomes admin; redirect to `/g/<slug>`.
  - `renameGroup(groupId, name)`.
  - `inviteAdmin(groupId, email)`: validate email and lowercase it. If a user with
    that email already exists, add the membership directly; otherwise upsert the
    invite.
  - `revokeInvite(inviteId)`.
  - `removeMember(memberId)`: this also covers leaving; enforce the last-admin guard.
- Update `games.test.ts`: mock `@/lib/auth`'s session as null and assert
  `Unauthorized` for representative actions across all three files. Add a
  cross-group test where the session user is an admin of group A, the record is
  in group B, and the result is `Unauthorized` (mock prisma).

## Task 4 — Landing, sign-in, groups dashboard

## Task 5 — Group pages + nav
- Move `game/new`, `game/[id]`, `players` and `stats` under
  `src/app/g/[slug]/...` using `getGroupForViewer(slug)`. A missing group is
  `notFound()`. Non-admins get:
  - game page: `redirect('/v/<viewSlug>')` if ACTIVE, else `notFound()`
  - new, players, stats: `redirect('/g/<slug>')`
- All queries are filtered by `groupId`, and the game page checks
  `game.groupId === group.id`.
- `src/app/g/[slug]/page.tsx`: the admin view is the old home list, filtered by
  group, plus "Start a new game". The public view shows only ACTIVE games, as
  cards linking to `/v/<viewSlug>`, with `Poller` so a newly started game shows up;
  otherwise "No game live right now".
- `BottomNav`: group-scoped tabs (Games `/g/<slug>`, Roster, Stats, Settings),
  rendered only on `/g/<slug>/*` for admins. Pass `isAdmin` from a
  `src/app/g/[slug]/layout.tsx` rather than the root layout. Add a small "← My
  groups" link in the group header for admins.
- Delete `src/app/live`, `src/app/game`, `src/app/players` and `src/app/stats`.
  `ShareLink` stays. `PageShell`'s bottom padding must still clear the nav when
  it's shown.
